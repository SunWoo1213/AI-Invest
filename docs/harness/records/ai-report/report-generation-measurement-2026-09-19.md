# AI 리포트 생성 반복 측정 — 통과율 · 비용 · 실패 원인 (2026-09-19)

## 목적
README 한계 절의 "리포트 품질 · 비용 실측 없음"을 해소한다. 같은 조건으로 리포트를 여러 번 생성해 통과율, 건당 비용 · 시간, 실패 원인을 숫자로 남긴다.

## 방법
- 대상: 스케줄러 대상 5개 자산(`DGS10`, `XAU`, `BTC-USD`, `NVDA`, `005930.KS`) × 4회 = **20건**, 2026-09-19 22:08~22:35(KST).
- 호출: `generate_report_for_ticker(ticker, db)`를 **한 건씩 별도 프로세스**로 호출(사용자 요청 경로와 같은 함수, 스케줄러 대신 스크립트).
- 환경: 로컬, 임시 SQLite DB(운영 DB 미사용), 실제 OpenAI(`gpt-4o-mini`) · 시세 API. 설정은 `.env` 그대로 + `ENABLE_AI_REPORT_GENERATION=true`.
  `REPORT_MAX_REVISIONS=7`, `ENABLE_REPORT_EVALUATOR=true`(기본값), `ENABLE_LLM_REPORT_CRITICS=false`, `REPORT_CRITIC_MODE=deterministic`.
- 측정: 결과(저장/거부), `revision_count`, 폴백 여부, LangChain `get_openai_callback`의 토큰 · 호출 수 · 비용, 경과 시간, 게이트별 실패 로그 수.

## 해석

1. **LLM 편집장이 사실상 모든 리포트를 거부한다.** 결정론 게이트 3개를 모두 통과한 초안도 편집장에서 FAIL → writer로 돌아가 재작성 한도를 소진한다.
   - 프롬프트가 `"{current_year}년 최신성"`만 말하고 **오늘 날짜와 데이터 기준 시각을 주지 않는다.** 피드백 11건 중 4건이 "현재 시점과의 차이"를, 1건은 "현재 시점이 2023년"이라고 판단했다(모델 학습 시점 기준으로 2026년 데이터를 미래 · 비최신으로 봄).
   - "하나라도 미흡하면 FAIL, 완벽하면 PASS" 기준이라 무료 API 데이터 한계(뉴스 비어 있음, 밸류에이션 · 베타 누락)도 FAIL 사유가 된다(3건).
2. **저장된 5건은 모두 편집장을 거치지 않았다.** 숫자 정제 폴백(`_attempt_numeric_sanitization_fallback`)은 형식 · 숫자 · 정성 게이트만 다시 돌리고 편집장은 부르지 않는다. 즉 지금 설정에서 저장되는 리포트는 "숫자 게이트에서만 실패했다가 폴백으로 살아난 것"뿐이다.
3. 형식 게이트 실패는 XAU(자산군 토픽 "계절성")와 005930.KS에 몰려 있다.
4. 비용은 건당 약 $0.013이라, 스케줄러 기준(5개 자산 · 6시간 주기, 하루 20건) 하루 약 $0.25 수준이다. 다만 대부분 재작성 한도를 다 써서 비용의 대부분이 거부되는 초안에 쓰인다.

## 개선 후보 (미적용 — 사용자 결정)
- 편집장 프롬프트에 오늘 날짜 · `data_as_of`를 넣고, "데이터 한계가 리포트에 표기되어 있으면 감점하지 않는다"는 기준을 명시(게이트를 느슨하게 하는 것이 아니라 판단 근거를 주는 것).
- 편집장 FAIL 피드백 유형을 로그로 집계해 결정론 게이트로 옮길 수 있는 항목 분리.
- 폴백 저장본도 편집장 판정을 기록(저장 여부와 분리)해 품질 추적.
- XAU "계절성" 토픽 요구가 수집 데이터로 뒷받침 가능한지 재검토.
